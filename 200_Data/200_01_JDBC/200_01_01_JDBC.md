### 1.2.2 Multiple datasource 

https://stackoverflow.com/a/52348520

If you need to configure multiple data sources, you have to mark one of the DataSource instances as **`@Primary`**, because various auto-configurations down the road expect to be able to get one by type.

If you create your own DataSource, the auto-configuration backs off. In the following example, we provide the exact same feature set as the auto-configuration provides on the primary data source:



    firstDataSourceProperties has to be flagged as @Primary so that the database initializer feature uses your copy (if you use the initializer).

```java
@Bean
@Primary
@ConfigurationProperties("app.datasource.first")
public DataSourceProperties firstDataSourceProperties() {
    return new DataSourceProperties();
}

@Bean
@Primary
@ConfigurationProperties("app.datasource.first")
public DataSource firstDataSource() {
    return firstDataSourceProperties().initializeDataSourceBuilder().build();
}

@Bean
@ConfigurationProperties("app.datasource.second")
public BasicDataSource secondDataSource() {
    return DataSourceBuilder.create().type(BasicDataSource.class).build();
}
```


**nd your `application.propoerties` will look something like this:**

```java
app.datasource.first.url=jdbc:oracle:thin:@localhost/first
app.datasource.first.username=dbuser
app.datasource.first.password=dbpass
app.datasource.first.driver-class-name=oracle.jdbc.OracleDriver

app.datasource.second.url=jdbc:mariadb://localhost:3306/springboot_mariadb
app.datasource.second.username=dbuser
app.datasource.second.password=dbpass
app.datasource.second.driver-class-name=org.mariadb.jdbc.Driver
```

The above method is the correct to way to init multiple database in spring boot 2.0 migration and above. More read can be found [here](https://docs.spring.io/spring-boot/docs/current/reference/htmlsingle/#howto-two-datasources).

# 2 @Bean, @Primary , @Qualifier

- In Spring Boot, the @Bean annotation is used to define and register a Spring-managed bean in the application context.
- If your application has multiple data sources and you want one as the **default**, use `@Primary`:
- `@Primary` tells Spring **which bean to use by default** when multiple beans of the same type exist.
- `@Bean(name = "...")` gives the bean a specific **name** so it can be manually referenced using `@Qualifier`.

DataSourceConfig.java
```java
@Configuration
public class DataSourceConfig {

    // You are explicitly naming this DataSource bean as "mysystemDataSource".
    // 如果 只用 @Bean() , 为空话 , 则  这个 DataSource bean 的名字 为 DataSource 这个 function name  = mysystemDataSource. By default, if a method is annotated with @Bean without a name, the method name (mysystemDataSource) becomes the bean's name.
    @Bean(name = "mysystemDataSource")  
    @ConfigurationProperties(prefix = "spring.mysystem.datasource")  // Then Spring Boot will map the properties from `application.yaml`:
    @Primary // This will be the default DataSource if no qualifier is specified
    public DataSource mysystemDataSource() {
        return DataSourceBuilder.create().build();
    }

    @Bean(name = "otherDataSource")
    @ConfigurationProperties(prefix = "spring.other.datasource")
    public DataSource otherDataSource() {
        return DataSourceBuilder.create().build();
    }
}
```


application.yaml
```yml
spring:
  mysystem:
    datasource:
      url: jdbc:postgresql://localhost:5432/mysystemdb
      username: myuser
      password: mypassword
      driver-class-name: org.postgresql.Driver

  other:
    datasource:
      url: jdbc:postgresql://localhost:5432/otherdb
      username: otheruser
      password: otherpassword
      driver-class-name: org.postgresql.Driver
```


**Testing the Connection**
To check if the database connection works, add this in a `@Service` class:
```java
@Autowired

// Ensure correct DataSource is injected
// If no `@Qualifier` is used, Spring will **automatically inject** the `mysystemDataSource`, because DataSource bean mysystemDataSource is defined as primary DataSource bean through @Primary 
@Qualifier("mysystemDataSource")  
private DataSource dataSource;

public void testConnection() throws SQLException {
    try (Connection conn = dataSource.getConnection()) {
        System.out.println("Connected to DB: " + conn.getCatalog());
    }
}
```


Retrieving the Bean by Name
You can retrieve a named bean manually:
```java
@Autowired
private ApplicationContext applicationContext;

public void getDataSourceByName() {
    DataSource ds = (DataSource) applicationContext.getBean("primaryDataSource");
    System.out.println("Retrieved DataSource: " + ds);
}
```
